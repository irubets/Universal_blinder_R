# Change history

## 3.0.0 (2026-11-04): R package with a Shiny app

- **Shiny app** (`run_app()`), the main way to use the tool: tabs Workflow, Study, Prepare PC, Study settings, Codebook review, Blind & QC, Retrieve, AI assistant, Setup/About.
- **Study folder** `UB_<StudyNumber>` created inside the study's own folder; datasets found under the study folder are listed with their profile and copied to `input` on request. Paths can be chosen in a folder tree or pasted, with or without quotes.
- **Settings** in `blind_options.json` (edited in the app; `blind.R`, `prepare_pc.R`, `retrieve.R` read it too).
- **Workflow 2** (PC delivered without results): `ub_prepare_pc()` puts the lab's results into PC before blinding. PC without results is now a check with a reminder to copy the lab file, and "Continue anyway" instead of a hard stop.
- **Codebook:** `CHECK` column for rows needing a decision; highlighted HTML and Excel copies; decisions made in Excel are imported back.
- **BQL/BLQ:** both `BQL<(x)` and `BLQ<(x)` are recognised; the LLOQ inside is blinded.
- `drop_vars`, `blank_where`, `analyte_numeric.precision_from`; pre-flight check (`ub_preflight()`); `ub_publish_check()`.
- **Study tab:** the *Copy selected files to input* button sits above the dataset table and shows how many rows are highlighted; the instructions say that clicking a row highlights (selects) it. Dataset roles: PP/ADPP are *linked: PK parameters* and ADPD *linked: PD* (selected by default with the targets and exposure); ADSL/DM *subject-level (optional)*, not selected by default. A test checks that linked values (USUBJID/SUBJID, PPCAT = PCTEST, PPRFTDTC = PCRFTDTC, PPSPEC = PCSPEC, VISIT, ATEST, AGE/WGTBL) still match after blinding.
- **Pre-flight: apply suggestions.** Highlight pre-flight rows and click the green *Apply* button (shows the count): the suggested `drop_vars`, `extra_suppress_vars` and `config_overrides` are written to the study settings with a backup, lists are merged, and the pre-flight runs again. The input datasets are never changed. Suggestions offering a choice or a condition are not applied and are named in the message. Step-by-step instructions above the table. `ub_preflight_apply()`.
- **Study tab: saved settings.** Card *3. Status* lists the choices saved in `blind_options.json` that differ from the defaults (they are next to `input`, not in `private`, so deleting `private` keeps them), with a *Reset settings to defaults* button (asks first; keeps a backup). `ub_settings_changes()`, `ub_reset_options()`. User guide: *Start a study again from scratch*. The same box, with its reset button, is shown below the Pre-flight table (a reset there runs the pre-flight again).
- **Stale R session:** `run_app()` and the app warn when the package was reinstalled after the R session loaded it (restart R to run the new code).
- **Dose per m² (BSA leak):** the pre-flight finds DOSEP levels given per m² from the data (median DOSEA/DOSEP between 1.1 and 3) and shows two rows, `dose_reveals_bsa`: DOSEA (STRONGLY RECOMMENDED to leave out; red while QC would fail) and DOSEP (optional). Either or both can be applied. A `blank_where` rule now counts in the pre-flight only when its condition variable exists in the dataset (a DOSEPU rule did not cover an ADPP without DOSEPU). Fixed: DOSEP was taken as its own unit variable, so "DOSEP has no unit" was never reported.
- **Workflow 3: release the lab file blinded** when its results can't be put into PC (times don't line up, rows missing on one side). Switch in *Prepare PC* (card 4, `lab_release` in `blind_options.json`), with *Check matching* (`ub_lab_release_prepare(write = FALSE)`). The lab file becomes LABPC, blinded in the same run as PC (same key and factors, same QC, verify), and is released as `output/<lab file>_blinded.csv` in the lab's own layout plus `UBRECID`, `LAB_ROW`, `PC_UBRECID` (the matched PC record) and `MATCH_STATUS`. Lab subjects not in PC are left out and reported. New QC WARN `lab_match_rate`. Retrieve maps lab findings back to the original lab rows. The app proposes Workflow 3 after an unmatched Prepare PC run, in the PC notice, in the "PC has no results" window, and in the Pre-flight.
- **Fixed:** QC stopped with an internal error when a dataset had no result at all (PC blinded without results).
- **Codebook review confirmation:** when no codebook row needs an answer, the reviewer types their name and clicks *I have reviewed the codebook* (`ub_codebook_confirm_review()`; name, time and a fingerprint of the codes in `private\codebook_review.json`). In the app, *Run blinding* starts only on a confirmed codebook (after the first run); a changed or new code needs a new confirmation, a NOTE does not. Shown in the Codebook review, Run blinding, Study and Workflow tabs. `ub_codebook_review_status()`. `blind.R` checks it too: `ub_blind_folder(require_codebook_review = TRUE)` (also used by the app) stops before anything is written, with the R command to confirm; the default `FALSE` keeps direct calls unchanged.
- **Pre-flight:** an empty table says *Nothing left to decide*; otherwise a note says that rows left in the table stay as they are by the user's choice.
- **User guide:** new section *The workflow at a glance* with a diagram (`inst/app/www/docs/workflow.svg`, also shown in the app), and Workflow 1 rewritten as 7 steps with the pre-flight loop, the codebook loop, the confirmation and what to do when nothing was released. `USERGUIDE.html` is built from `USERGUIDE.md` by `tools/build_userguide.R` (pandoc, self-contained).
- **Codebook review in the app:** step-by-step instructions saying that `codebook.csv` never needs to be opened; highlight amber rows and click *Mark the highlighted rows as decided* (empties CHECK and saves, with a backup); a green *Codebook review done* box links back to *2. Run blinding*. The Run blinding hint says the review is done in the app.
- **NOTHING WAS RELEASED explained:** after a QC FAIL, the *Run blinding* tab lists the failed checks (instead of "See the log below"), with buttons to open *1. Pre-flight* and *3. QC result*, and *Ask the AI why*, which opens the AI assistant (triage task) with the QC findings and a filled-in question. The log is never sent.
- **DOSEP released as a whole number** (dose category, rounded half up); the source keeps its value.
- **Run blinding tab:** the "first run stops once for the codebook review" note is now a highlighted box with a link that opens the *Codebook review* tab. It is shown only before the first run and while codebook rows are still open, and disappears once the review is done.
- **AI assistant suggestions:** highlighted rows are applied with one green *Apply* button (shows the count); triage and "unexpected input" suggestions (`path = value`) can now be applied to the settings, list settings such as `drop_vars` are merged rather than replaced, and rows that only explain are never applied. A send error (e.g. local model timeout) no longer stays on screen after switching models, and no longer hides later answers.
- **App address and layout:** the app always opens at `http://127.0.0.1:3838` (a free port is used, with a message, if 3838 is taken). Pages scroll normally and tables are as tall as their rows, so answers, suggestion tables and buttons below them are no longer hidden inside a card.
- **AI assistant:** Claude (Anthropic API) or a local model (Ollama, OpenAI-compatible). Strict data split: real values never go to the cloud; every Claude request is checked and blocked on any real value.

Based on the earlier R package (2.0.0).
